## Pay-run amounts at rest (decision)
Compensation (the source of pay), identity numbers and bank accounts are encrypted per field. **Pay-run results are not**, and this was decided, not forgotten:
- The database itself guards them: triggers freeze the items and lines of a locked run and compare totals; unique and check constraints work on the numbers; reports total them in SQL. Ciphertext columns would move all of that into application code, where a bug or a direct SQL statement could bypass it. For payroll, tamper-evidence is worth more than a second layer of confidentiality.
- Locked rows may never change. Encrypting them later, or rotating a key, would mean rewriting frozen legal records with the triggers switched off.
- Field encryption does not stop the realistic attacker here: someone with application access already sees decrypted values, and someone with only the database has no key but, with the controls below, no access either.

What protects them instead: permissions and separation of duties in the application, a fresh password check and an audit entry for every read, least-privilege database roles (I14), encrypted backups, and disk encryption on the server **[yours]**. Revisit the decision if the database is ever shared with another system or hosted where the provider's staff can read volumes.

## Known gaps (accepted for now, tracked)
- The built-in payroll rules were checked against their sources (`31-hr-regulatory-validation.md`): TER tables, PTKP, BPJS ceilings by period, daily TER and the December true-up. Sign-off by a tax consultant is still **[open]**, as are the documented assumptions (BPJS on back-dated pay, the base for daily workers, part-year tax subjects).
- Pay-run amounts are numbers, not ciphertext (see the decision above).
- Virus scanning needs the ClamAV service (`ops/docker-compose.ops.yml`) and `Antivirus__Enabled=true`; without it uploads are only type-checked. Files are stored in the database (fine for contracts, ID scans, receipts and photos, not for large archives).
- Payslips and letters carry a verification code checked with the issuer; they are **not** signed with a certificate (no certified electronic signature under UU ITE). See `33-hr-security-self-assessment.md` §5 for what adding one involves.
- Weekly pay is an interim payment settled monthly. The official 1721-A1 / e-Bupot upload format is not produced; the system exports the A1 data as CSV for entry into Coretax.
- No independent penetration test yet; the self-assessment and the tester's brief are in `33-hr-security-self-assessment.md`.
- Dependency audit (2026-11-10): `npm audit` and `dotnet list package --vulnerable` report 0 vulnerabilities (PostCSS inside Next.js is pinned through an npm override; re-check when upgrading Next).
